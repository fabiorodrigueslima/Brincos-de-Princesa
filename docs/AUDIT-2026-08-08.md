## 1. Resumo executivo

O projeto tem uma boa fundação para o catálogo público: React/Vite, API Express em camadas, PostgreSQL sem ORM, SQL parametrizado, validação Zod, CORS por allowlist, Helmet, rate limit, 26 tabelas e constraints relevantes. A API pública e o banco real responderam corretamente em estados vazios.

O projeto ainda não é uma loja virtual operacional. Não existem carrinho, cotação autoritativa, checkout, criação de pedidos, pagamento, autenticação, autorização administrativa, painel, uploads ou CRUD administrativo. O banco contém quatro categorias e quatro configurações; todas as demais tabelas estão vazias.

Há bloqueadores antes de avançar:

- navegação interna pode deixar toda a interface em branco por retorno inválido no efeito ScrollToTop;
- dois testes PostgreSQL existentes falham no banco atual porque dependem de fixture externa e não preparam o próprio cenário;
- não existe repositório Git no diretório;
- duas páginas apresentam scroll horizontal entre 320 px e 390 px;
- o papel brinco_app possui permissões além do menor privilégio necessário;
- não há testes de frontend, E2E, acessibilidade ou concorrência de estoque.

### Defeito alto de navegação

frontend/src/components/common/ScrollToTop.jsx:6 usa um callback de efeito com retorno implícito:

    useEffect(() => window.scrollTo(...), [pathname])

Efeitos React só podem retornar uma função de limpeza ou undefined. No navegador testado, window.scrollTo retornou um valor não-função. Resultado observado:

- desenvolvimento: React registrou “destroy is not a function” e a tela ficou em branco;
- build de produção: carregamento direto funcionou, mas clicar no link interno /sobre mudou a URL e deixou o snapshot DOM vazio.

Correção proposta, não executada: usar bloco no efeito, sem retornar o resultado, e adicionar teste de navegação mais Error Boundary.
